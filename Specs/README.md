# Decisions written in t27

Every decision Ponte makes is written in [t27](https://github.com/gHashTag/t27), the spec language of the Trinity stack, and compiled to C with `t27c gen-c`. Swift collects the facts (device names and transport types, audio blocks, the volatile text, timings, what the person clicked), asks a spec, and carries out the answer through the system APIs and the views.

Three Swift facades stand between the app and the C: `AudioRules` (PonteAudio), `SpeechRules` (PonteSpeech) and `AppRules` (PonteApp). Their function bodies only marshal: they copy text and samples into the fixed buffers the C takes, pass offset and length tables, turn optionals into a flag and a value, and map codes. Constants come from the C `#define`s. The Swift each facade replaced is kept, renamed, in `Tests/PonteTests/Oracles/` (`AudioRulesLegacy`, `SpeechRulesLegacy`, `AppRulesLegacy`) as the oracle of the differential tests. Each spec function's comment names the Swift it mirrors.

## Calling the C from Swift

`import PonteSpecs` gives the constants (`#define`s; Swift imports integers as `Int32` and decimals as `Double`, so the facades convert them) and the prototypes. Types follow the facades: `Int` is `int64_t`, `Int32` codes are `int32_t`, `Float` is `float`, `Double` is `double`, `UInt32` and `UInt64` stay unsigned.

- **Float buffers** are fixed blocks: a mono block holds `AU_BLOCK_FRAMES` (4096) samples, an interleaved or planar block `AU_BLOCK_SAMPLES` (8192), an RMS block `SG_RMS_BLOCK` (4096). A `[N]f32` parameter is `float x[static N]` in C: the facade copies an `N`-element scratch buffer and processes longer buffers block by block. `au_sum_squares_continue`, `au_peak_continue` and `sg_sum_squares_f32` carry a running sum or peak across blocks in index order, so the result equals one pass over the whole buffer.
- **Tables of integers** (`[64]i64` byte sizes and channel counts of an AudioBufferList) are copied the same way. `AudioRules.bufferListShape` fills them on the stack (`withUnsafeTemporaryAllocation`), because `PCM.downmixFloat32` runs on the HAL's real-time thread.
- **Text** is UTF-8 bytes. `device_rules` takes every string as an offset and a length into one `text` buffer of `DV_TEXT_MAX` (8192) bytes, and a list of strings as parallel `offsets[256]`/`lengths[256]` arrays with a count. `segment_rules` takes a buffer of `SG_TEXT_MAX` (8192) bytes with its length, `voice_rules` one of `VO_ID_MAX` (1024), `transcript_rules` input and output buffers of `TR_BUFFER` (4096), `ui_rules` a launch flag of `UI_WORD_MAX` (64) and a source key of `UI_KEY_MAX` (4096). Outputs are written to an out-buffer and the function returns their length. Words the app writes (`"pid."`, `"system"`, `"app:"`, effort names, preferred voice names) come from the specs' byte tables.
- **Optionals** become a flag and a value (`has_voice`, `voice_start`); Swift enums (`Lang`, `Direction`, `CaptureMode`, `PTTKey`, `TranslatorKind`, `PermissionState`, `Check`, the OS statuses) become the specs' codes.
- **Packed steps** (`ln_gate_step`, `ln_phrase_step`) return `(state << 8) | action`, read back with `ln_step_state` and `ln_step_action`.
- **Fixtures.** `*_FX_*` constants and `sg_fixture`, `dv_fixture`, `dv_fixture_push`, `vo_fixture`, `tr_fixture`, `tr_fixture_matches` hold the UTF-8 texts the specs' own tests use (t27 has no byte-string literals that reach C). The app does not need them.

## Regenerate

```bash
T27C=~/Documents/t27-v051/target/release/t27c ./Specs/generate.sh
```

The script:

1. runs `Specs/tables/ponte_tables.py`, which writes the byte tables (device words and the `pid.` prefix, the known call apps sorted by bundle ID with their labels, the FaceTime companions, novelty-voice parts and preferred voice names, effort names, source keys and launch words) and the test texts into the specs between the `; >>> generated` markers;
2. checks the whole tree with `t27c parse-complete` (no spec may be truncated or lose tokens) and `t27c check-calls` (every call matches its callee);
3. for each spec runs `t27c check` (warnings are printed), `t27c gen-c`, and the spec's own tests with `xcrun clang -std=c11 -ffp-contract=off -Wall -Wshorten-64-to-32 -Wno-parentheses-equality -Werror -DT27_TEST_MAIN`, and checks that every `test` block ran;
4. writes `Sources/PonteSpecs/<spec>.h` (the full C, compiled once by `Sources/PonteSpecs/t27_specs.c`) and `Sources/PonteSpecs/include/<spec>.api.h` (constants and prototypes), and rewrites `include/ponte_specs.h` (the umbrella Swift imports) and `t27_specs.c`.

Files are copied only when their content changed. The generated C is committed, so `swift build` and `scripts/bundle.sh` never need `t27c`. `T27C_PIN` names the compiler the committed C was generated with. `-ffp-contract=off` is required wherever the C is compiled (Package.swift sets it for PonteSpecs): a fused multiply-add would change the float results in the last bit.

## Tests

- **Spec tests.** Each spec's own `test` blocks (38 in all) run in `generate.sh`. They carry the facades' test cases and, where the input space is small, exhaustive loops (every flag set, state and event of the state machines; every byte for the text rules; every chunk split).
- **C from Swift.** `Tests/PonteTests/SpecsTests.swift` calls every spec through its C API, checks the constants that must equal system values (Core Audio transport types, `AVAudioCommonFormat`, `AVAudioConverterInputStatus`, `AVAuthorizationStatus`, `AVSpeechSynthesisVoiceQuality`, `NSEvent.ModifierFlags.function`, `AudioApp.knownCallApps`) and the codes one spec produces and another reads (`AU_MIC_REQUEST_FIRST` = `LN_MIC_REQUEST_FIRST`, `CX_AVAIL_*` = `UI_AVAIL_*`, `SG_LANG_*` = `VO_LANG_*`).
- **Differential.** `*RulesDifferentialTests.swift` and `*MovedRulesDifferentialTests.swift` (46 tests) compare every facade function with its oracle, bit for bit: exhaustive sweeps over small domains (every `Int16`, every flag combination, every code, every byte of a four-char code, every half millisecond in ±10 s) and seeded random inputs with edges (0, −0, negative, `Int.min`/`Int.max`, NaN, infinities, subnormals, UTF-8 multibyte and invalid bytes, empty lists, texts longer than the buffers). One run checks about 23.6 million cases; floats compare by bit pattern, NaNs regardless of payload. `VoiceActivity` is also run over long random level streams (more than 256 closed segments) against a meter assembled from the oracles.
- **Mutation check.** A rule flipped in a generated header (`ms <= UI_LAT_GOOD_MS` to `<`; `audio_end >= t − tolerance` to `>`) fails `swift test`.

## Domains and known differences

- Buffers bound the inputs: device texts 8192 bytes and 256 strings; phrase texts 8192 bytes (`cutByteIndex` exact for `maxBytes` below 8190); voice identifiers 1024 bytes; Markdown escaping 2048 bytes of input; a launch flag longer than 64 bytes is never "yes"; at most 64 buffers of an AudioBufferList and 64 planar channels; 8192 interleaved channels. Longer inputs are clamped where Swift would read the whole array.
- Equality of texts is byte equality; Swift's `String ==` also equates canonically equivalent forms. Device names, UIDs and bundle IDs arrive in one form, so the results agree in practice.
- The app tells BlackHole by `AudioRules.isBlackHole` (ASCII case-insensitive, the same rule as the device kinds) where it used PonteCore's `AudioDevice.isVirtualMic` (`localizedCaseInsensitiveContains`). They differ only for non-ASCII letters that fold to ASCII, such as the Kelvin sign.
- `SourceChoice` reads the `app:` prefix of a stored key by bytes; `String.hasPrefix` compares characters, so a combining mark right after `app:` would differ. Bundle IDs are ASCII.
- Transcript lines are ordered by time, then by their order in the call: the stable sort Swift's `sorted(by:)` performs, now stated.
- `SystemSpeechSynth.voice(for:)` reads the best installed voice even when a saved voice exists, because the rule takes both facts; the chosen voice is the same.
- Integer overflow and out-of-range float-to-integer conversions trap in Swift and are undefined in C; the facades never pass such values.

## Compiler notes (t27c v0.5.1)

- A one-element array literal breaks `gen-c`; `ponte_tables.py` refuses to write one.
- An unused `pub const` array fails the tests (`-Wunused-const-variable`); a test that passes an array literal produces invalid C. Tests use named arrays.
- Constants become untyped `#define`s; a negative one is written without parentheses (`#define AU_DBFS_FLOOR -120.0`), so the specs never write `-CONST`.
- `sqrt`, `floor`, `round` and `abs` (as `fabsf`/`fabs` through `_Generic`) pull in `<math.h>`; other libm calls (`log10f`, `ceil`) compile only in a spec that already uses one of those.
- `cast_i64(x)`, `cast_u64(x)` and the other integer casts also convert floats (C truncation), without the typecheck warning a typed `var` gives.
- Every condition is emitted in double parentheses; `t27_specs.c` turns off `-Wparentheses-equality`.
- Test function names must be unique across all specs.
- `t27c check` warns about functions with more than 8 parameters (`dv_is_tap_target_process` has 9); the warning does not stop generation.
